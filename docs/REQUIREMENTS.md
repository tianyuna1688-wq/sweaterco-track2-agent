# Track 2 实施依据与验收映射

本平台按用户提供的产品说明实现，业务事实优先顺序为：原始 `harness/simulate.py` 与官方数据字典、v3 CHANGELOG、课程 v4 的 Track 2 要求、产品说明中的建议设计。HTML 内的教学代码没有被当作已验证实现。

## 源文件核对

原始目录：`/Users/tinas/研究生/自己做的项目agent/track1/track2`。工作区保存原始数据和模拟器的逐字节副本，`docs/source/manifest.json` 记录 SHA-256；评估每次都重新校验 7 个文件，任何不一致会阻止运行。原始目录未修改。

| 事实 | 实施与证据 |
| --- | --- |
| 120 订单、8 工坊、30 请求 | `backend/app/data_access.py` 读取并验证；`evals/labels.json` 覆盖30条原文 |
| 默认三项资格检查 | 复用官方 `eligible_workshops`：ACTIVE、类别、单批上限 |
| 可选工序扩展 | 默认关闭；开启时必须覆盖当前工序到 PACKING，单独评估文件 |
| 聊天时间口径 | 固定 2026-04-01，不能用电脑当前日期替换 |
| 模拟回放口径 | 2026-01-01 开始；忽略厂内历史状态列；每周7天；一批一家 |
| 运输与队列 | 运输计入交付时间，不能加到工坊下一单生产队列 |
| 缺陷 | 批次概率 `defect_rate`，发生则额外生产半批；期望生产量乘 `1 + 0.5p` |
| 日期 | 官方绝对日 `round`；同时显示独立 `ceil` 保守日期，二者明确区分 |
| 约束与副作用 | 排除工坊在Python层过滤，来源写入结构化记录；当前只建议，不真实下单 |

Factory Primer 提到厂内周一至周六工作，但官方外包模拟器明确工坊每周7天生产。平台按外包模拟器计算，不把厂内日历应用到工坊。

## 需明确保留的限制

- 无模型凭证时是受限的中英文规则解析器，不能将30条规则测试成绩称为LLM准确率。未知句式需要追问；线上模型表现需另外评估。
- 拆分是两个工坊的独立假设试算，未计入官方成绩，未更新真实队列。
- 三情景日期是模型假设下的估计，没有额外的物流、节假日或生产保障数据。
- 官方测试集小且开发期已知，100%（如达到）仅表示该测试集通过，不能证明开放域泛化。
- 本地演示的单用户访问边界不能替代公网多租户认证；上线范围以部署说明为准。
